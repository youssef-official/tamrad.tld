
# خطة تجربة الزبون (Customer App)

بناء تجربة زبون كاملة على صفحة المطعم `/r/:slug` مع صفحات حساب مستقلة.

## 1. قاعدة البيانات (Migration)

جدول جديد `customer_addresses`:
- `id, user_id (FK auth.users), label` (بيت/عمل/…)
- `full_address, city, notes`
- `latitude, longitude` (اختياري)
- `is_default boolean`
- `created_at, updated_at`
- RLS: كل مستخدم يقرأ/يكتب/يحذف عناوينه فقط
- GRANT للـ `authenticated` + `service_role`

## 2. إجبار تسجيل الدخول قبل الطلب

في `src/routes/r.$slug.tsx`:
- زر "أضف للسلة" و"إتمام الطلب" يفحصان `supabase.auth.getUser()`.
- إذا لا يوجد مستخدم → توجيه إلى `/auth?redirect=/r/{slug}`.
- تصفح المنيو يبقى مفتوحاً بدون تسجيل — الحد فقط عند الطلب.

## 3. بانر تثبيت PWA + شرح مبسّط

مكوّن جديد `<InstallAppBanner />` أعلى صفحة المطعم:
- على Android/Chrome: يستخدم `useInstallPrompt()` الموجود (زر "ثبّت التطبيق").
- على iOS Safari: يعرض تعليمات مصوّرة قصيرة ("اضغط مشاركة → إضافة إلى الشاشة الرئيسية").
- يُخفى بعد التثبيت أو الإغلاق (يُحفظ في localStorage).

## 4. دفتر عناوين الزبون (متعدد العناوين)

- في `Checkout` الحالي: بدل حقل العنوان النصي → قائمة عناوين المستخدم + زر "➕ إضافة عنوان جديد".
- عند فتح `Checkout` لأول مرة بدون عناوين → يُطلب من المستخدم إضافة عنوان قبل المتابعة.
- العنوان المختار يُنسخ إلى `orders.address` و`orders.delivery_notes` كما هو الآن (بدون تغيير مخطط `orders`).

## 5. صفحات حساب الزبون

تُضاف تحت `src/routes/_authenticated/`:

| الصفحة | الوظيفة |
|---|---|
| `account.tsx` | لوحة الحساب: الاسم، الهاتف، تسجيل الخروج، روابط للصفحات أدناه |
| `account.addresses.tsx` | إدارة العناوين (CRUD + تعيين افتراضي) |
| `my-orders.tsx` | كل طلبات المستخدم السابقة (فلترة `customer_id=auth.uid()`) — إعادة الطلب بزر واحد عبر `reorder_from` RPC الموجودة |
| `my-coupons.tsx` | أكواد الخصم المخصّصة له (من جدول `coupons` حيث `assigned_user_id=auth.uid()`) + جوائز الولاء |

## 6. شريط تنقّل سفلي للزبون (Bottom Nav)

مكوّن `<CustomerBottomNav />` يظهر في:
- `/r/:slug` (صفحة المطعم)
- صفحات `/account*` و`/my-orders` و`/my-coupons` و`/orders/:id`

روابط: **المطعم • طلباتي • الأكواد • حسابي**

## 7. ملاحظة بخصوص مناطق التوصيل

طلبك: "المناطق مو محدودة، صاحب المطعم يضيف المنطقة ويحدد سعرها".
الوضع الحالي **يفعل ذلك فعلاً**: في `/dashboard/zones` صاحب المطعم يضغط "إضافة منطقة" → يكتب اسم المنطقة والسعر (`fee_iqd`) بحرية بدون قائمة ثابتة. لا حاجة لتغيير هنا — إذا كان قصدك شيء آخر أخبرني.

## التفاصيل التقنية

- استخدام React Query keys: `customer-addresses`, `my-orders`, `my-coupons`.
- الوصول للجداول عبر client المتصفح مع RLS (نفس النمط الحالي، لا خوادم إضافية).
- كل الصفحات RTL عربية، بنفس تصميم النظام الحالي (design tokens).
- روابط `/r/:slug` تظل عامّة (لا `_authenticated`) — الحماية على مستوى الأزرار فقط.
